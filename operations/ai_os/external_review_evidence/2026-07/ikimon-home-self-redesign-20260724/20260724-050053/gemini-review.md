# 防護策（Defensive Safeguard）監査レポート：ikimon.life ログイン後画面再設計

## 1. 判定 (Verdict)
**変更付き承認 (Approve with changes)**

> **承認条件:**
> 以下に示す「極めて深刻度の高いセキュリティ・プライバシー上の欠陥」5点に対する具体的な防護策（地名・画像のセーフガード、 IndexedDB のマルチユーザー隔離、提案アルゴリズムの保護対象エリア除外）を実装計画（P0/P1）に義務付けること。

---

## 2. 深刻度順のトップ指摘事項 (Top Findings)

### 【Finding 1】希少種（Endangered Species）の画像・地名による「ビジュアル・ジオロケーション」リスク
- **深刻度:** **Critical（最重要・環境及び安全）**
- **対象:** `6.3` 「粗い地名（Coarse Place Name）」および「最近の写真」表示
- **リスク:**
  絶滅危惧種や希少種のデータについて、単に地名を「粗いレベル（例：〇〇市）」にするだけでは不十分。背景に写り込んだ特徴的な樹木、巨石、地形（ビジュアル・ジオロケーション要素）と「粗い地名」を組み合わせることで、悪意ある密猟者やコレクターが数時間以内に正確な生息地を特定し、乱獲するリスクがある。
- **防護策:**
  - 希少種に該当する投稿がHomeの「最近」「見返す」などのサムネイルに表示される場合、**画像全体に強力なブラー処理（ぼかし）を自動適用するか、汎用の「希少種アイコン」に動的に差し替える**こと。
  - 地名ラベルは市町村レベルではなく、**都道府県レベル（あるいは「特定保全エリア」などの完全マスク文字列）に強制フォールバック**するロジックをP0に組み込むこと。

### 【Finding 2】「場所の続き」「次の活動」による子供・要保護エリアへの危険誘導とストーキングリスク
- **深刻度:** **High（高・物理的安全・ストーキング防止）**
- **対象:** `6.2` `recent_memory` の「同じ場所で撮る」CTA、`6.3` `場所の続き` / `次の活動`
- **リスク:**
  子供の自宅、通学路、学校、あるいはプライベートな私有地をユーザー自身が「場所」として登録していた場合、システムが「場所の続きをしよう！」「もう一度訪れてみよう」とHome画面で繰り返しリコメンド（CTA提示）を行うのは極めて危険。子供が同一の行動パターンを繰り返すように誘導される結果になり、ストーカーによる待ち伏せや、私有地への無断侵入（Trespassing）をアルゴリズムが助長する危険性がある。
- **防護策:**
  - 既存の位置保護ルール（自宅、学校、プライベート空間、危険エリア）でフラグが立っている場所、および子供アカウントの行動範囲に関連する「場所」は、**「場所の続き」「次の活動」「同じ場所で撮る」といったあらゆる行動レコメンド対象から構造的に除外（ブラックリスト化）**すること。
  - Homeに表示する「場所の続き」は、行政や公共団体が管理する「公的な自然公園・公共保全地域」に限定すること。

### 【Finding 3】デバイス共有環境における IndexedDB 下書きのマルチユーザー漏洩
- **深刻度:** **High（高・データプライバシー）**
- **対象:** `6.2` `draft_resume` (IndexedDB からの未完了下書き復元)
- **リスク:**
  ikimon.life のような市民参加型サービスでは、1台のタブレットやPCを親子、あるいは学校のクラスで共有して交互にログインすることが頻繁にある。IndexedDB 内の下書き（ドラフト画像、メタデータ、高精度GPS）が「単一のクライアント側ストレージ」として雑に保管されていると、A君がログアウトした後にB君がログインした際、A君の自宅付近で撮った未公開の下書き写真や正確な位置情報がHome画面に露出（`draft_resume` として表示）してしまう。
- **防護策:**
  - IndexedDB 内の下書きデータは、必ず **`userId`（暗号化ハッシュ）を主キーとしたパーティショニング（隔離保管）** を徹底すること。
  - セッション変更時（ログイン・ログアウト）に、クライアント側のストア状態を完全に破棄し、ログイン中の `userId` に一致するドラフトのみをロードする検証ゲートをP0に必須要件として追加すること。

### 【Finding 4】プッシュ通知・反応プレロードによる機密情報のサイドチャネル漏洩
- **深刻度:** **Medium（中・プライバシー）**
- **対象:** `6.2` `new_response` (未読リアクション・コメントのHome表示)
- **リスク:**
  「〇〇さんがあなたの投稿を『確認』しました」というHomeでの差分表示において、元の投稿が高精度な位置保護エリア（自宅等）や、非公開の「共有圏」に属している場合、反応メッセージのテキストやサムネイル、あるいはペイロードデータから、間接的に第三者に位置・行動が漏洩する可能性がある。
- **防護策:**
  - `new_response` でレンダリングされる通知コンポーネントは、バックエンド側で完全にサニタイズされた（位置情報、機密画像を含まない）非公開通知用の専用スキーマを使用すること。
  - フロントエンド側で元の詳細データにシームレスにJOINして復元するような、クライアントサイドでの「特権データ結合」は、認証認可チェックを二重に行わない限り原則禁止とする。

### 【Finding 5】Object URL のメモリリークとライフサイクル管理の不確実性
- **深刻度:** **Medium（中・技術的レジリエンス）**
- **対象:** `9.0` P0 開発の「Object URL は画面離脱時に解放」
- **リスク:**
  下書き復元時のサムネイル表示において、「画面離脱時（`beforeunload` や `unload` イベント）に Object URL を解放する」という設計は、iOS Safari や Android Chrome などのモバイルブラウザ（PWA含む）では**極めて不確実**。OSによるプロセスの突然のサスペンドやバックグラウンド破棄により、メモリーリーク（メモリ bloat）が発生し、アプリの異常終了やINP（Interaction to Next Paint）の著しい劣化を引き起こす。
- **防護策:**
  - 画面離脱イベントに依存せず、**コンポーネントのアンマウント・ライフサイクル（React の `useEffect` クリーンアップ関数、または Vue/Svelte の destroy フック）内で、即時かつ確実に対象 Object URL を `URL.revokeObjectURL()` する**設計に書き換えること。

## 3. 不足している仮定やエビデンス (Missing Assumptions/Evidence)

1. **共有圏 (Sharing Circle) の強制オプトインと招待承諾フローの未定義:**
   - 「自分」ページ（P2）で家族・学校などの共有圏を扱う際、「誰がグループに招待できるのか」「承諾（Consent）なしに自動でグループに入れられて写真を共有されることはないか」のロジックが未定義。招待は「承認待ち」状態を挟み、オプトインした時のみデータをHomeに表示する前提が必要。
2. **「粗い地名（Coarse label）」の正確な生成ルール:**
   - メタデータの位置情報からどのように「粗い地名」に変換するのか（逆ジオコーディングの解像度フィルター）。メッシュ単位での丸め処理なのか、市区町村名なのか。境界線上にある場合に誤って細かい施設名（例：〇〇小学校）が露出しないためのフィルター仕様が欠落している。
3. **オフライン・オンライン間の同期競合:**
   - IndexedDB に下書きがある状態で、別端末から本番保存された場合のクエリ同期の挙動。同一データが重複してHomeに露出するのを防ぐ「冪等性キー（Idempotency Key）」の存在が示されていない。

## 4. 具体的な変更推奨策 (Concrete Recommended Changes)

- **P0 フェーズの必須改定案:**
  - **下書きのマルチユーザー分離:** `selectMemberHomeState()` 内で、IndexedDB クエリにアクティブなユーザーIDをバインドし、他人の下書きを絶対にロードさせないテストコードを構築する。
  - **Endangered Species Safeguard（希少種保護フィルター）の組み込み:** Homeのファーストビュー画像レンダラーに `isEndangered` チェックを入れ、該当する場合は画像をボカすか placeholder に差し替えるロジックをP0の段階で入れる。
  - **Object URL ライフサイクルの変更:** 技術設計から「画面離脱時解放」を削除し、「DOM非表示/コンポーネント破棄時に即時 revoke」に修正。

- **P1 フェーズの必須改定案:**
  - **「場所の続き」推薦フィルター:** 保護地域（自宅、学校、未公開の私有地）を推薦アルゴリズムのソースから除外するセキュリティクエリを追加。

## 5. 却下・延期すべきリスク (Risks to Reject/Defer)

- **「顔認識」や「近接検知」に基づく自動共有サジェスト（完全却下）**
  - Google/Apple Photos にある「一緒に写っている家族に自動共有」や「同じ場所・時間にいたグループに自動追加」といった自動化機能は、同意の境界線を曖昧にし、子供たちの意図しない写真露出事故を招く。ikimon.life において、これらはP2であっても**一切導入すべきではない**。
- **Homeにおけるユーザー同士の「未読コメント数」や「リアクション数」のバッジ競争（完全却下）**
  - バッジ数の強調は一般的なSNSでの認知心理的ハック（比較・競争）を生み出し、市民参加の健全性を損なう。バッジによる煽りは排除し、具体的な「中身（誰々さんが反応してくれた）」を優しく伝えるUIに留めること。
