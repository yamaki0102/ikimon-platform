### 2. Top findings ordered by severity (重大度順の検出事項)

#### 🚨 Finding 1: 位置情報・撮影日時の残存リスク (EXIF / プライバシー防衛) — **Severity: Medium**
* **詳細:** 本プラットフォームは「いきもの（生物）」の観察記録を扱う性質上、絶滅危惧種の生息地秘匿や、ユーザーの自宅周辺といった位置プライバシーの保護が極めて重要だよ。
* **リスク:** 動的画像変換プロキシ（`/derived-transform/`）を経由していた時は、プロキシ側が動的にメタデータを削除して WebP に最適化して配信していた可能性がある。今回 R2 のオリジナル（`display.webp`）をクライアントに直接配信するようにバイパスすることで、もしインポート処理の段階で EXIF メタデータ（GPS 座標や正確な撮影日時）の削除（Strip）が行われていない場合、第三者にユーザーの正確な位置情報や行動履歴が露出してしまうリスクがあるよ。

#### ⚠️ Finding 2: キャッシュバスター（クエリパラメータ）によるバイパス失敗 — **Severity: Low**
* **詳細:** 実装コードでは `url.endsWith("/display.webp")` でバイパス判定を行っている。
* **リスク:** 将来的にクライアント側のキャッシュクリアやバージョン管理、あるいは CDN の制御目的で、URL の末尾にクエリパラメータ（例: `/display.webp?v=20260723` や `?ts=12345`）が付加された場合、この `endsWith` 判定が `false` になり、画像変換プロキシ（404 ルート）に再度フォールバックして、再び画像が表示されなくなる先祖返りが発生するよ。

#### ℹ️ Finding 3: エラーハンドラーによる画像の即時完全消失挙動 — **Severity: Low**
* **詳細:** 404 エラー発生時にエラーハンドラーが画像を DOM から即座に削除する仕様になっている。
* **リスク:** 一時的なネットワーク瞬断や CDN のキャッシュ更新の遅延など、回復可能なエラーであっても無条件で「代表画像自体が画面から完全に消え去る」という挙動は、やや過激でユーザーを不安にさせるね。将来的にプレースホルダー（代替画像）の表示やリトライ制御への緩和を検討する余地があるよ。

### 3. Missing assumptions or evidence (欠落している前提・エビデンス)

1. **インポート時のメタデータ（EXIF）処理に関する保証の欠落**
   * インポート元（Place Atlas API）から取得して R2 に格納される `display.webp` は、格納される時点で「すでに EXIF データなどのプライバシー情報が完全に削除・クレンジングされている」というバックエンド側の保証（実装仕様）があるかどうかのエビデンスが、本レビューパケットからは確認できなかったよ。
2. **変換プロキシの仕様境界**
   * なぜ `/derived-transform/` が `/derived/import/` 配下の有効な公開 WebP 画像を解決できない（404 になる）設計になっているのか（例えば、プロキシが参照するオリジンストレージのパスにインポート用バケットが含まれていないなど）、根本的なアーキテクチャ境界のドキュメントが不足しているよ。中長期的にはプロキシ側を修正すべきかどうかの整理が必要だね。

### 4. Concrete recommended changes (具体的な推奨変更案)

#### 【推奨】クエリパラメータを許容するロバストな前方・後方一致判定への変更
クエリパラメータが将来付与されても安全にバイパスできるよう、URL パス部分のみを取り出して判定する形式、または正規表現での判定にアップデートすることを推奨するよ。

**修正案 (TypeScript):**
```ts
// Imported display.webp assets are already bounded R2-backed public derivatives.
// クエリパラメータ（?t=xxx など）があっても安全にパス部分で前方・後方判定を行う
const urlPath = url.split('?')[0];
if (urlPath.startsWith("/derived/import/") && urlPath.endsWith("/display.webp")) {
  return url;
}

if (url.startsWith("/derived/")) {
  return `/derived-transform/w${width}/${url.replace(/^\/+/, "")}`;
}
```

#### 【確認タスク】インポートバケットのプライバシー・監査
1. バックエンドのインポートバッチ処理において、`display.webp` 生成時に `imagemagick` や `sharp` 等で `-strip` (メタデータ削除) が確実に行われていることを確認してね。

### 5. Risks that should be rejected or deferred (却下または延期すべきリスク)

* **画像変換プロキシ（Wrangler/Worker等）自体の即時回収・拡張 (Deferred)**
   * 「プロキシが `/derived/import/` を直接解決できるようにプロキシサーバー側のコードを修正する」アプローチは、今回の緊急ホットフィックス（Hotfix）のスコープとしては複雑度が高すぎ、デプロイ検証ラインを破壊する恐れがあるため、今回は明確に**延期（Defer）**すべきだよ。まずはクライアント側のこのホットフィックスで止血するのが大正解。
* **クライアント側での EXIF 動的解析・削除処理の追加 (Rejected)**
   * ブラウザ側で直接バイナリをロードして EXIF を削除するような処理を追加することは、表示パフォーマンスの大幅な劣化とクライアント負荷を招くため、完全に**却下（Reject）**するよ。プライバシー防衛は常に「アップロード/インポート時」のサーバーサイドで行うのが鉄則だからね。
