# ADR-0001: 最初に閲覧価値を得られ、状態を誤認しないZUKANの画面設計

- 状態: 採用済みの設計判断
- 日付: 2026-09-05
- 正本: ../ZUKAN_APP_EXPERIENCE_V1.md §16
- 範囲: UI/UXの設計。実装割当・キュー昇格・追加deployの指示ではない。

## 背景

公開Homeと記録・地図で主ナビが重複・不一致になり、写真の大きさで題名や日時が見えにくい。未同定の表示が記録の題名を置き換え、端末の下書き・保存・AI・人の確認・公開・外部掲載も、ひとつの完了状態として受け取られやすい。

## 採用する判断

1. 共通ナビを一本化し、初訪問のHomeは公開記録への到達を主操作にする。撮る入口と写真中心の始めやすさは保つ。
2. 画面の役割で情報密度を変える。記録一覧では題名・日時・場所を写真と同時に読み、詳細は内容と根拠に集中する。
3. 保存、AI、名前の確認、内容Review、公開範囲、配信条件、実際の掲載は、既存の意味と対象を分けた表示にする。
4. 不一致・欠落・失敗を、成功・非公開化・掲載済みへ推定変換しない。表示材料がない機能の成功画面を作らない。
5. 既存の色・ロゴ・媒体・ルートを使う。新しいデザインシステム、管理画面、共通DB、確認エンジンは増やさない。

## 採用しない判断

- すべての初訪問者を認証・撮影から始めさせること。
- 地名候補を正式なPlace、AI理由を人のReview理由、配信可能を掲載実績とすること。
- 紹介写真不足を架空の写真・件数・地域実績で埋めること。
- 設計が決まったことを実装済み・本番検証済みとすること。

旧Homeの一律「撮る」を主CTAとする規則は、未認証・投稿権限が未確立の初訪問者に限って本判断が置き換える。ログイン後のHomeと記録中の主操作は状態に従う。
