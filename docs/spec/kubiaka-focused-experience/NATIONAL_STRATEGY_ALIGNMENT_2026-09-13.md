## 1. 根拠と確認範囲

依頼者が提示した2026-09-11の日経記事は、環境省・農林水産省による防除戦略決定、国・都道府県・市町村の役割、4地域区分、市民の発見情報を報じている。この記事は依頼時に提供された資料として扱う。

一次情報の参照先は農林水産省の[2026-09-11対策本部開催案内](https://www.maff.go.jp/j/press/syouan/syokubo/260911.html)。開催案内だけで戦略本文の全条件や、各市町村への区分指定まで検証済みとしない。実際の表示・連絡先登録時には、その用途に必要な正式文書の版と適用条件を取得する。

## 2. 日本向けに採用すること

「見つける → 写真と場所を残す → 確認できた範囲を返す → 連絡内容を整理する → 公式窓口へ進む → 必要なら再訪する」をクビアカの具体的な利用体験とする。

保存・AI処理・専門Review・通報・行政受付・現地対応は共通契約で独立して扱う。AIや人Reviewを待たずに公式窓口へ進める。ZUKANへの保存と自治体への通報を同じ完了表示にしない。

初期実装はprivate保存、本人への返却、連絡用情報と出典付き公式窓口まで。API連携・自動送信・専門家対応・地域担当者の確保を実装済みと表示しない。

## 3. 4地域区分の表現

依頼資料の `未被害地域 / 飛び地的被害地域 / 被害最前線地域 / まん延地域` は、日本の当該制度の原文ラベルとして保持できる。

共通Coreへ4値enumを固定しない。regional policyの `original_scheme / original_code / original_label / jurisdiction_ref / effective_time / source_edition` へ対応付ける。

区分定義が公表されていることと、特定自治体がその区分に指定されていることを分ける。指定が未取得ならunknown。ZUKAN内の投稿がないこと、投稿数、AI候補の分布から未被害・まん延を判定しない。

## 4. 連絡先

実際の発見地域、土地利用、寄主や発見内容、時点に適用する公式案内を用いる。農地とその他の樹木で窓口が分かれる例として、[長野県の公式案内](https://www.pref.nagano.lg.jp/nogi/kubiaka.html)がある。この分岐を全国へ無条件に適用しない。

県、市町村、農業窓口、施設管理者のどこへ知らせるかは、regional policyの適用条件で解決する。位置が不明・行政境界付近・資料が矛盾する場合は候補と未確認事項を出す。電話・form・email等の入口を案内できることは、受信機関とのAPI契約があることを意味しない。

浜松等の実際の専用受理契約、専門家、処理能力、SLAは未確定。空欄を架空の運営体制で埋めない。

## 5. 安全・写真・地図

撮影は安全な範囲で行い、対処は対象地域の公式案内へ接続する。国の記事だけを根拠に、全利用者へネット施工・伐採・薬剤使用・捕殺等を一律に指示しない。

素材は公式ページで公開されていても、再利用条件・credit・加工条件を画像ごとに確認する。「環境省提供」と記載すればどの画像でも使えるという許可を作らない。

本人記録、管理対象の再訪一覧、担当者向けmonitoringを優先する。公式に公開された地域状況と、市民のprivate座標は別データ。国の可視化方針からraw市民投稿の公開許可を導かない。
