# ADR-0001: 共通Recordと限定mailbox権限による無人利用開始

## Context

[SPEC.md](../SPEC.md) の市民ログイン不要・自治体の無人開設を、現行Worker/D1/R2で実現する。イベントguest credentialと共通の写真準備・Record/asset保存、通常会員の認証sessionは既に存在する。一方、イベント参加や通常会員権限だけでは、市民が指定した自治体へ特定項目を提供する権限を表現できない。

## Decision

写真は共通の `draft_observations`、`observations`、`asset_ledger` に保存し、Target Profile・匿名所有・用途別共有の小さいcontextを追加する。媒体を自治体ごと、種ごとにコピーしない。確定前は予約とleaseを保持し、同じ要求でR2またはD1の不確定な結果から再開する。

eventで使用するCSPRNG、cookie名生成、digest、厳密なcookie読取りを共有部品にする。biosecurityは用途別cookieを使い、event参加者・通常会員との暗黙の結合を行わない。guestの原記録を目的別共有から独立して保護するためである。

自治体の公式ドメイン根拠とmailbox所有者の確認を別段階にする。J-LIS由来の固定自治体ID・公式サイトを基準にし、台帳外ドメインを申請者の自己申告URLから承認しない。公式サイトの明示mailboxを容量・時間・回数の上限内で照合できた場合だけ、一回限りのメールコードを発行する。根拠不足を手動承認フローへ流さず、権限を付けない状態と公式窓口を表示する。

担当者のsessionは既存 `auth_sessions` に格納し、専用cookie、短い期限、`MunicipalInbox` role、municipality membershipで限定する。このroleは通常の会員sessionリゾルバーから拒否する。メール一致を根拠に既存accountを引き継がない。公式メール確認は組織全体の代表権限や公認表示ではないため、管理者roleや全private記録を付与しない。

明示的な市民の宛先・目的・項目同意を閲覧の根拠とし、受信箱の開設とは独立させる。未開設の自治体への共有はその状態を表示し、自治体担当者の確認操作も正式通報の受付とは区別する。撤回と期限は取得の直前・直後で再確認する。

## Consequences

自治体・対象が増えてもサーバー・保存先・認証実装を複製しない。初期費用を抑えるため、AI、全件の専門家確認、無制限の画像保管を必須にしない。既存送信bindingを上限付きで使い、無料枠の残量未確認を追加費用0円の保証に置き換えない。

cookie消去後の別端末復元、公式ページに掲載されていないmailboxの自動認証、既に相手が保存したコピーの回収は保証できない。実自治体のメール到達と実利用成立はsource試験から推定せず、運用証拠として別に確認する。
