## 背景と目標

対象は生物調査の熟練者だけではありません。

- ウォーキング、犬の散歩
- 子どもとの散歩、公園遊び
- 胸部・頭部へスマホを固定した徒歩調査
- 車載ホルダーへ固定した車両通過調査
- 一地点へ固定する定点調査

利用者は開始後、基本的にスマホを操作しません。カメラ、位置情報、必要時の自然音から、調査時間・範囲・方法・代表フレームを自動的に残します。気になった対象だけ手動シャッターまたは一定時間の静止によって、通常の個別記録候補へ昇格させます。

既存のAIガイドや音声案内は調査記録の成立条件から外し、任意の別レイヤーにします。

体験の中心は次です。

> いつもの散歩や移動が、地域の調査量を少し進めたと分かる。

## 現時点の仮説

以下は確定仕様ではありません。誤りがあれば明確に否定してください。

1. 徒歩・車・定点は開始時に利用者が選択し、GPS速度はモード判定ではなく撮影頻度等の補助にだけ使う。
2. 徒歩は約10秒ごとに候補フレームを取得するが、端末内で重複・ブレ・暗所等を除き、代表フレームのみ保持する。
3. 車両は時間固定ではなく、距離・速度・方位変化・画像差分で候補を選ぶ。渋滞や信号待ちでも徒歩へ切り替えない。
4. 胸部・頭部固定時の不安を減らすため、一定間隔で「実際に有効フレームを端末保存できた」ことを短い振動・音等で知らせる。
5. AI解析やサーバー送信に成功しなくても、端末内へ調査台帳が保存できた時点で調査成立とする。
6. オフライン中も開始・継続・終了・即時結果まで成立させ、後で安全に同期する。
7. 500m程度のメッシュごとに、調査日数、調査時間、参加人数、季節、最終調査日、調査方法を集計する。
8. 将来的にメッシュ内部の未調査部分や、道路・水路・公園・土地利用と既存調査を重ね、「この付近を見られるとよい」を提示する。
9. 個別記録は既存の豊かなフィードバックへ接続し、調査モード全体には別の「調査レシート」を返す。
10. 終了押下後はネットワークやAIを待たず、ローカル結果を即表示し、後続解析はレイアウトを崩さず追加する。

## 必須レビュー観点

### 1. ブラウザだけで成立する範囲

- iOS Safari、Android Chrome、PWAを含む実際の制約
- カメラ、マイク、Geolocation、速度・方位、Screen Wake Lock
- 前面・画面点灯・バックグラウンド・画面ロック時の挙動
- 30分以上の連続利用における電池、発熱、メモリ、帯域、端末差
- 胸部・頭部・車載固定で「動いている」と保証できる範囲
- ブラウザ実装で無理なものと、将来ネイティブ化すべき境界

### 2. 現行実装の事実確認

- 何が既に実装され、何が見かけだけ・未完成・危険か
- `guideFlow.ts`へ機能が集中していることの影響
- 現在の撮影・音声・telemetry・AI送信・DOM更新が終了後のかくつきや長時間劣化を起こし得るか
- offline queue、保存期限、同意スナップショット、再送契約にデータ消失・再送不能・プライバシー上の穴がないか
- 既存機能を再利用すべき範囲と、作り直すべき範囲

### 3. UX

- 開始前、調査中、手動記録、終了直後、後日フィードバックを一本の体験として評価
- 画面を見ない利用者への正常通知と異常通知
- 定期通知が煩わしい、自然観察を邪魔する、録音へ混入する等の副作用
- 親子、徒歩、運転者、同乗者、定点で分けるべきこと
- 運転中の操作を誘発しない安全設計
- 「数字が増えた」以上の自己効力感を、誇張せず返す方法

### 4. 調査努力量としての妥当性

- 自動撮影、GPS通過、音声、手動記録をどう区別するか
- 徒歩・車両・定点を同一スコアへ混ぜる危険
- 撮影時間、移動距離、撮影方向、位置精度、季節、時間帯、参加人数の扱い
- 「探したが見つからなかった」と単なる通過を混同しない契約
- 同一人物・同一路線・連続セッションによる水増し
- 市民向けの簡潔表示と、研究・行政向けの透明な内訳の両立

### 5. 調査量マップと次地点提案

次を難易度別に分解してください。

- 500mメッシュの調査量表示
- メッシュ内部の25〜50m程度の撮影・通過カバー
- 撮影方向や道路片側への偏り
- 道路、水路、公園、農地、土地利用、季節を使った不足地点提示
- オフライン中の周辺カバーデータと地図キャッシュ
- AI不要で実現できる範囲
- GIS・統計で実現する範囲
- 画像・音声AIが必要になる範囲
- 精度が足りず表示してはいけない範囲

### 6. データモデルとアーキテクチャ

必要なら、現行schemaを読み、以下を提案してください。

- SurveySession / EffortObservation / CoverageCell / CaptureCandidate等の境界
- 生データ、代表フレーム、個別記録、集計、派生分析の分離
- append-only、再集計、重複排除、削除・同意撤回
- 公開500mメッシュと非公開ルートの分離
- PostgreSQL / D1 / R2 / IndexedDBの責務
- migrationが必要か、必要なら最小単位とrollback条件
- 巨大な単一UIから分割する責務と状態機械
