# 連理の木の下で サイエンスアドベンチャー — 当日fallback card

参加者向け時間: **11:10–13:00**

目的: ikimon.lifeの不調でイベント体験や参加者の写真を失わせない

## 最初の30秒

1. 写真・入力を消さないよう案内する。
2. 同じ操作を何度も繰り返させない。
3. 影響が「1端末 / live・位置だけ / 投稿全体 / privacy」のどれかを判断する。
4. 判断責任者へ時刻と影響範囲だけを伝える。個人情報、token、座標をチャットへ送らない。

## Fallback 1 — 写真記録を継続

発動条件:

- live表示だけが不調
- 位置共有だけが不調
- recapの演出だけが不調

行動:

- 不調機能の案内を止める。
- 位置共有をOFFのままにする。
- 写真撮影・保存とイベント体験を継続する。
- 参加者へ「みんなの表示は後で確認します。写真はそのまま残してください」と案内する。

## Fallback 2 — 端末に写真を残す

発動条件:

- 投稿APIや画像uploadが複数端末で失敗
- 通信復帰後も保存成功を確認できない
- 登録またはcheck-inが繰り返し止まる

行動:

- 参加者のスマートフォンで写真だけ撮る。
- 元写真を削除・加工・共有しないよう案内する。
- 紙には受付番号、撮影時刻の目安、会場内の大まかなゾーンだけを書く。本名、メール、正確な座標は書かない。
- 後日投稿方法は責任者が別途決める。当日その場で個人LINEやメールの収集を始めない。

案内文:

> 写真はスマホに残っています。いまは撮影を続けて、送信は後で確認します。写真を削除せず、そのままお楽しみください。

## Fallback 3 — ikimon.lifeを必須から外す

発動条件:

- join/auth/runtime全体が利用できない
- 写真や入力の消失が疑われる
- 他家族の情報、正確な位置、credentialが見える
- productionとstagingの境界が分からない

行動:

- QRとikimon.lifeの操作案内を止める。
- 紙またはスタッフ端末で、受付番号ごとの発見数だけを記録する。
- 写真は各端末に保持し、イベントの観察・共有・ブルーベリー体験を継続する。
- privacy問題では画面を全体表示せず、責任者だけがevidenceを保全する。
- 現場でproduction deploy、DB編集、secret変更、データ削除を行わない。

案内文:

> 今日は写真と発見を楽しむ形で続けます。撮った写真はスマホに残し、発見数はスタッフが記録します。

## 復帰条件

- 原因が特定され、対象端末1台でcheck-inまたは保存成功を確認できた。
- 写真・入力消失、credential漏えい、他家族情報の露出がない。
- 判断責任者が復帰を明示した。

復帰できても一斉再送させない。1組ずつ確認し、retry stormと重複投稿を避ける。
