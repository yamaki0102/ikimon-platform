## 1. テスト前提

- 対象SHAとstaging URLを固定する。
- production participant dataを使わない。
- 専用fixtureまたはテスト用アカウントだけを使い、写真は人物を含まない専用素材にする。
- 個人名を記録せず、`R1-P01`、`R2-P01`の匿名IDを使う。
- テスターへ、画面・音声・操作記録の用途と保存期間を説明し、同意を得る。
- facilitatorは操作方法を教えない。安全・privacy・端末破損の懸念がある場合だけ停止する。
- observerとnote takerは可能ならfacilitatorと分ける。

### Facilitator script

テスターへ伝える文は次の1文だけにする。

> QRを読み、イベントに参加して、名前の分からない生き物の写真を1件残し、みんなの発見を見てください。

質問された場合は「実際のイベントだと思って、ご自身の判断で進めてください」と返す。操作の場所、登録方法、位置共有、戻り方を教えない。

### Tasks

1. QRからイベントを開く。
2. 家族・グループとして参加する。
3. 名前の分からない生き物の写真を選ぶか撮る。
4. 観察を保存する。
5. みんなの発見を見る。
6. recapを見る。

### Round 1判定

- 合格目安: 5人中4人以上が主要taskを口頭介助なしで完了。
- QR→参加の中央値: 30秒以内。
- QR→最初の観察保存: 2分以内。
- 5人中2人以上が同じ箇所で止まれば、個人差ではなくUI問題として扱う。
- 改善は説明文追加だけに寄せず、ボタン、順序、初期値、画面数、状態表示を優先する。
- メール、password条件、確認メール、登録後の戻り、下書き消失で2人以上が失敗した場合は、登録flowの簡略化または安全な当日fallbackを判断する。
