# Frontend Foundation next promotions

Current evidence supports only a small next set.

1. Complete the shared token layer with spacing before adding more visual tokens.
2. When an existing sheet/dialog surface is next changed, reuse shared focus/close/escape/reduced-motion behavior instead of creating another local variant.
3. When toast or async feedback is next changed, converge its state semantics on the Foundation contract.
4. Treat chat-specific components as NOCOSIL-first candidates; promote cross-product only after reuse is proven.
5. Keep maps, field capture and event composition product-local unless behavior, not appearance, repeats.

Do not create a generic component package, Storybook, registry server or framework migration from this evidence alone.
