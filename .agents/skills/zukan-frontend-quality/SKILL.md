# ZUKAN frontend quality

## Resolve the bounded job

Fresh-read the relevant NOCOSIL Work/Current State, root `AGENTS.md`, `DESIGN.md`, and `docs/frontend-foundation/README.md`. Reuse existing `design-quality-router` and `ui-quality-gate` when available; this skill is a project adapter, not another design authority.

Write three short statements in the existing Work: the user's main action, the current visible problem, and the intended improvement. Classify the surface as product or marketing. ZUKAN includes places, nature, culture, history, work, and everyday life; do not narrow the product to wildlife or copy another product's personality.

## Implement the smallest coherent change

Reuse existing renderer, tokens, components, and verification commands. Do not add a UI framework, Figma dependency, animation package, registry, or test service for stylistic improvement alone. Do not append another CSS override when the existing owner of the declaration can be corrected.

Keep navigation roles, capture behavior, authentication, publication/consent, and location protection unchanged unless explicitly in scope. Public-list eligibility is not Home-promotion permission. Empty states must remain honest and composed; never fill them with invented records, stock photos presented as records, or private material.

## Inspect, critique, correct

Capture before and after at smartphone, tablet, and desktop sizes with real Japanese copy. Include 320/375px, 768px, and 1280/1440px for redesigned pages; test 1160/1161px when shared navigation changes. Inspect the images, not only the DOM or a screenshot count.

Review hierarchy, type, spacing, section relationships, image/no-image states, control consistency, wrapping, and fixed-element overlap. Compare against the three statements above and correct visible defects. Pixel comparison detects change; it does not prove the design is good. Noah owns rendered acceptance; distinguish implementer review from a genuinely independent reviewer.

Check relevant keyboard/focus, target sizes, hidden/permission states, reduced motion, overflow, console errors, and primary interactions. Keep the existing map-performance guard when its surface or shared shell is affected. Use focused tests and proportional verification, not a new blanket pipeline.

## Close only the verified boundary

For materialized pages, rebuild and verify the registered UI artifact as well as the shared source. A component fixture, a local preview, a passing unit test, a merged commit, and a deployed runtime are different facts.

In the existing NOCOSIL Evidence/Resume record source SHA, URL or fixture provenance, viewport/state, screenshots actually inspected, check results, reviewer verdict, and unresolved boundaries. Never label a fixture as staging, source merge as production, or unavailable persistence as saved. If the authorized runtime or storage route is unavailable, preserve a compact pending handoff and stop at that boundary without weakening access controls.
